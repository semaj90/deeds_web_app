# Feature × Spec × Implementation Audit (2026-05-11)

> Counterpart to `file-move-audit-gates.md`. Where that doc verifies *refactor safety*, this doc verifies *feature delivery* — what AGENTS.md / `master_agents.md` say should exist, what code actually exists, and where the two diverge.

---

## 0. Methodology

This audit answers four questions per feature area:

1. **What does the spec say?** — sourced from `sveltekit-frontend/docs/master_agents.md` (the master directory map, 1,480 lines), the top-level `sveltekit-frontend/AGENTS.md` (50KB, auto-regenerated by `npm run agents:write`), and 8 sampled directory-level `AGENTS.md` files (out of 383 total).
2. **Which files implement it?** — derived from `sveltekit-frontend/docs/graph/codebase-graph.json` (4.2MB, full file index from the May 10 graphify run) and `sveltekit-frontend/memory/atlas/codebase-atlas.dirs.json` (618KB, per-directory features). No new globbing — atlas was the source of truth for file counts.
3. **What imports are missing/broken?** — verified via targeted `Grep` for `from '$lib/server/<feature>'` consumers and the `npx svelte-check` baseline noted in CLAUDE.md (8 errors / 9 warnings in 11 files at start of session). `svelte-check` was attempted live but exceeded the 60s timeout window — relied on the documented baseline plus per-feature consumer counts as a proxy.
4. **Status classification** — `SHIPPED` / `PARTIAL` / `SPEC_ONLY` / `UNDOCUMENTED`, ruthless not generous (see §1 for definitions).

**Deliberately skipped:** exhaustive `svelte-check` per file, full DB live-comparison (relied on the May 10 `0 of 28 orphan-schema tables in DB` finding from prior session), full 383-AGENTS.md sweep (sampled 8 high-value dirs covering ace / vector / cache / gpu / grpc / agents-md / detective / courtroom).

**Definitions:**
- `SHIPPED` — spec'd, implemented, wired into ≥1 route or downstream consumer, no obvious broken imports.
- `PARTIAL` — implementation exists but at least one of: missing migrations, missing route surface, broken consumer chain, spec describes more than code delivers.
- `SPEC_ONLY` — referenced in `master_agents.md` or directory AGENTS.md but no functional implementation, or only a stub/orphan-schema definition.
- `UNDOCUMENTED` — substantial implementation exists in the tree with no corresponding spec entry in master_agents.md or directory AGENTS.md.

## 1. Top-Line Findings (TL;DR)

1. **HyperRAG 11-lane pipeline is the single best-spec'd-and-wired subsystem in the repo.** All 12 lanes (L0–L11 per `master_agents.md` §2) have a primary file in `src/lib/server/ace/`. `context-assembler.ts` is **3,911 lines** — the size matches the spec ambition. 20 imports from this dir into the rest of the codebase. **Status: SHIPPED.**
2. **Orphan schema files describe 28 tables that are not in `schema-postgres.ts` and not in the live DB.** Of 6 orphan schemas (`schema-phase78.ts`, `schema-gpu-cache.ts`, `schema-ingestion.ts`, `schema-week3-kb.ts`, `schema-test-rag.ts`, `schema-charges.ts`) only **3 have any consumer at all** (1 file each), and `schema-phase78` + `schema-week3-kb` have **zero imports anywhere**. These are `SPEC_ONLY`. The user's note (*"we've never migrate pushed all the tables"*) confirms this is the known unmigrated lane, not a regression.
3. **Cross-encoder reranker is built but unwired.** `src/lib/server/retrieval/cross-encoder-reranker.ts` exists, but `grep "from .*cross-encoder-reranker"` returns **0 consumers**. `master_agents.md` §6.1 lists it as HIGH PRIORITY missing — and that's still accurate. Status: `PARTIAL` (file present, no caller).
4. **MCP TRACE server is heavily over-spec'd vs the registration count.** `master_agents.md` line 21 claims "73 (TRACE :8788)" registered tools and the global memory log claims 88. The actual registration call-count in `trace-mcp-server.ts` is **74 `tool(...)` calls**. The May 9 mount-and-smoke report (`memory/architecture/mcp-mount-smoke-2026-05-09.md`) was more honest: 42 tools register cleanly after the per-request transport fix, the rest are silent-failing in 5 registries (adminTools / skillTools / codebaseTools / bifrostTools / topologyMgmtTools). **Spec drift: ~31 tools are claimed but mounted-but-broken.** Status: `PARTIAL`.
5. **Reconstruction 3-track architecture is `SPEC_ONLY` for tracks B/C/D.** `src/lib/server/reconstruction/` ships scene-intent extractor + compiler + crime-scene schema (Track A only). No ComfyUI render queue consumer (despite `src/routes/api/comfyui/render/` existing as a route shell), no Blender Mixamo pipeline, no WebGPU low-poly renderer wiring beyond the `webgpu/gaussian-*` shaders.
6. **Karpathy GPU blend works but operates on n=11 instead of n≥65.** Per `master_agents.md` §5, the autoencoder fell back to Xavier random weights because top-50 PageRank files aren't yet in Qdrant. `gpu:karpathy:scores` exists in Redis but the 64-dim memory paths are semantically meaningless. Status: `SHIPPED with degraded output` (classified as `PARTIAL`).
7. **`src/lib/server/agents-md/` ships only 4 files** (`parse-agents-md.ts`, `resolve-directory-context.ts`, `schema.ts`, `AGENTS.md`) but the manual SQL `drizzle/manual/agents_md_relations.sql` defining `agent_context_files` / `directory_context_bindings` / `ace_context_sources` (per CLAUDE.md `## AGENTS.md Relationship Spine`) is **missing from `drizzle/manual/`** — the file does not exist in the manual SQL inventory (21 files listed, none matching). Persistence layer is `SPEC_ONLY`.
8. **Several substantial features are `UNDOCUMENTED` in `master_agents.md`:** the entire `src/lib/server/retrieval/` directory (32 files including `manifold4-search.ts`, `triton-reranker.ts`, `langextract-reranker.ts`, `legal-pagerank.ts`) is mentioned only obliquely; intent-dispatch (`/api/ai/intent-dispatch`, `/api/ai/contextual-chat`) is wired through `intent-router.ts` but neither feature appears in the master atlas's tracked feature list (18 entries).
