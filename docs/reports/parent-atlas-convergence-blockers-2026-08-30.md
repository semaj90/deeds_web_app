## 3. Graphify backfill still silently falls back to Ollama

The same committed script:

```text

- probes :8081
- if :8081 is absent, uses Ollama
- if :8081 fails mid-run, uses Ollama for the batch

```

That is incompatible with promotion-grade embedding provenance. A canonical writer must not silently switch embedding executors while continuing to write the same logical representation revision.

Required split:

```text

  legacy Ollama explicitly allowed
  no promotion receipt

PROMOTION/APPLY MODE
  :8081 required
  exact model/tokenizer/executor/artifact revisions required
  any executor failure => fail closed
```

Classification: `RUNTIME_BLOCKER` for `EMBED-8081-PROVE-01` and authoritative Graphify writes.

## 4. The committed backfill provenance is too weak

The script currently derives:

```text
embedding_version = sha256("semantic_768:graphify:${MODEL}:${contentHash}")
```

where `MODEL` may be the movable string `embeddinggemma:latest`.

This does not bind:

```text
upstream model revision
GGUF artifact SHA-256
llama.cpp build revision
tokenizer revision/checksum
pooling configuration
input/prompt policy revision
representation revision
executor role
```

A vector generated by two different runtime artifacts can therefore receive indistinguishable lineage if the tag and content are unchanged.

Classification: `LINEAGE_BLOCKER`.
