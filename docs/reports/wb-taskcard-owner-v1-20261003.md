# WB-TASKCARD-OWNER-01 — Task-card owner reconciliation

**Disposition: WB-TASKCARD-OWNER-01 PASS.** The task-card projection, selector, ranker roles, and manifest scopes are now separated. The 337/1,742 figures were not TaskCard unmatched counts; a fresh same-revision Workboard/TaskCard parity audit found no unmatched task identities. No shared corpus, task authority, database, vector, cache, graph, or archive data was changed; generated TaskCards were written only to ignored scratch storage.

## 2. Selector ownership

| Component | Classification | Observed behavior |
|---|---|---|
| `selectOpenSpecTaskCardsV1` in `scripts/atlas/lib/openspec-report-manifest-v1.mjs` | sole canonical `SELECTOR` for TaskCard retrieval/admission | Owns retrieval-state selection and optional lifecycle `cardStates`, records the states and exact returned-card checksum, and preserves default `CURRENT`, `WAITING`, `REVIEW_REQUIRED` visibility. `buildTaskCardCohortV1` now delegates filtering to this selector; it does not implement separate lifecycle admission. |
| `rankSelectedOpenSpecTaskCardsV1` in `scripts/atlas/rank-open-tasks-v1.mjs` | canonical TaskCard `RANKER` interface | Verifies the exact selector checksum/revisions and emits one result per selected card without filtering, re-reading source lines, changing selection, or writes. |
| `rankOpenTasksLegacyV1` / `rankOpenTasks` in `scripts/atlas/rank-open-tasks-v1.mjs` | `LEGACY` compatibility ranker | Retains raw Workboard eligibility behavior for compatibility; explicitly not the TaskCard selector or canonical ranker path. |

**Owner decision:** the TaskCard corpus builder owns the single task projection; `selectOpenSpecTaskCardsV1` owns the selected candidate set; `rankSelectedOpenSpecTaskCardsV1` owns advisory ordering only. Selection and ranking are separate. Selection defaults intentionally retain review-required rows for retrieval; callers that need an admitted subset must state lifecycle states explicitly. This is not execution authorization.

## 3. Ranker ownership

The TaskCard path in `rank-open-tasks-v1.mjs` is the canonical ranker interface, but currently produces only deterministic neutral identity ordering because TaskCards have no validated revision-bound rank features. It reports `NO_REVISION_BOUND_TASKCARD_RANK_FEATURES`; this is not meaningful task prioritization. The former raw Workboard ranker remains `LEGACY` compatibility and no ranker is canonical task-state authority:

```text
frozen admitted-card selector → rank-open-tasks scorer → advisory ordering
```

**Classification:** `rankSelectedOpenSpecTaskCardsV1` = canonical advisory interface, neutral mode; `rankOpenTasksLegacyV1` = `LEGACY`; no semantic or learned challenger is promoted. Ranking quality remains a later feature-matrix/tournament gate.

## 4. Manifest ownership

| Contract | Classification | Owns | Does not own |
|---|---|---|---|
| `ReportArtifactManifestV1` (`atlas.report-artifact-manifest.v1`) and `atlas.report-artifact-manifest-corpus.v1` | `MANIFEST` | One report/artifact per entry: path/artifact ID, checksum state, size, media type, producer metadata, task association state, replay/sensitivity disposition, storage class, and archive eligibility. | Workboard task-ledger/shard layout. |
| Workboard shard manifest (`atlas.workboard-report-manifest.v1`, `scripts/atlas/build-workboard-report-manifest-v1.mjs`) | `MANIFEST` | Shards of one generated Workboard ledger: source/canonical checksums, task/shard counts, key order, and per-shard IDs, paths, hashes, bytes, and row counts. | Per-report artifact identity, sensitivity/replay, or archive disposition. |

These contracts have non-overlapping artifact layers. Use `WorkboardReportManifestV1` only as a descriptive name for the Workboard/shard contract; the implemented schema ID is `atlas.workboard-report-manifest.v1`. Do not make the shard manifest a collection of `ReportArtifactManifestV1` rows or treat similarly named manifests as one owner.
