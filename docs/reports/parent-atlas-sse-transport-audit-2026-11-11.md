## What the app uses

- The evidence progress route is an authenticated SvelteKit `GET` returning `text/event-stream`. It reads durable history for the existing `analysis_jobs` owner and carries `eventId`, `jobId`, `evidenceId`, `caseId`, `stage`, `status`, `sourceRevision`, and progress.
- SSE and gRPC are separate transports. `EvidenceUploadProgress.svelte` uses browser `EventSource` to the SvelteKit route. Retrieval code uses `@grpc/grpc-js` server-side, normally at `127.0.0.1:50053`; the current retrieval adapter invokes unary `SearchCodebase`. No `StreamCodebase` caller was found. The Vite `/grpc` proxy points to `50051`, a different configured endpoint, and is not the evidence-progress path.
- Vite serves SvelteKit `/api` routes directly. `vite.config.ts` does not proxy the evidence SSE route. Caddy is the optional front proxy.

## Retry, dedupe, IDs, and scale

- Native `EventSource` owns reconnect delay and `Last-Event-ID`. The new `retry:` value varies by connection so mass reconnects are spread over a bounded interval. There is no app-managed retry timer for this stream.
- The server's `event_seq` is the replay cursor; persisted `event_id` is the UUID for stable event identity. The component drops any replayed sequence less than or equal to its last applied cursor.
- A reconnect can reach another SvelteKit worker if all workers share the same PostgreSQL history and equivalent session authorization. No sticky routing is required by the cursor contract. The reviewed Caddy configs each name one upstream, so no multi-upstream load balancing was found in those files.
- The route polls PostgreSQL once per second per open connection, emits 15-second heartbeat comments, caps each replay batch at 32 rows, and rechecks case authorization every 30 seconds. It now has configurable per-process, per-actor, and per-job admission caps (defaults 128/4/2) plus a 16 KiB bounded response queue. These counters are process-local: they do not enforce a global limit across multiple SvelteKit workers. Over-limit streams return 429 with `Retry-After: 5`; a chunk that exceeds remaining queue capacity closes the stream so EventSource can resume from its last cursor. Production fan-out still needs measurement and, if workers multiply, a shared coordination design.
