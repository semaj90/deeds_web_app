1. **Run read-only dependency inventory** across `services/`, `python/`, `sveltekit-frontend/`, and `scripts/` before retiring any `.backup` or `SUPERSEDED` modules.

   - `langextract` delegates LLM calls to `:8090` (`gemma4-legal-iq4xs-direct.gguf`) over `http://host.docker.internal:8090/v1`.
3. **Keep fixed-width hot buffers**: `PFB1` (104B header, zeroed tail bits/high nibble), `ARPC` (MsgPack/zlib/LZ4 + SHA-256, no Base64), `Arrow IPC` (`fixed_size_list<float32>`), and `Parquet` + `Zstd` for cold archives.

### P1 — Revision-Consistent Hybrid GraphRAG + PG18 Reconciliation (Target: 100%)
1. **Rebuild `legal-ai-go-retrieval`** (operator-authorized) so `:8100/search/codebase` emits live `query_stage_trace`.
2. **Refresh source authority first:** publish a stable workspace snapshot through the existing operator-reviewed source-index admission owner, refresh Graphify, and re-audit. The `.tmp` candidate is not canonical; do not reuse an old revision as if current.
3. **Wire Neo4j bounded 1-hop expansion**: Cap seeds, fan-out, time, and visited nodes; enforce `status = 'ADMITTED'` and `workspace_revision = $revision`.
4. **Full-corpus `turbo16`/`turbo8` benchmark**: First reconcile the current 76,000-point projection against the eligible PG18 cohort; then measure Recall@10/100, MRR, nDCG, and P95 latency against exact PG18 `<=>` before switching any Qdrant alias.
5. **Isolated `EmbeddingGemma 2` full-encoder experiment**: Use the Google retrieval query prompt and titled retrieval-document prompt on both sides; bind model digest, prompt revision, chunk/source revisions, and corpus/query checksums. Cap each input to the documented 8,192-token limit. Keep 768D as the first shadow baseline; evaluate 512/256/128 MRL only as separate, renormalized representations. Do not modify `semantic_768`.

### P2 — Codebase Semantic Indexing & WebGPU UI Pipeline (Target: 100%)
1. **Symbol-Aware Extraction**: Combine `rg` (direct arg array, bounded), `Tree-sitter` CST, `ast-grep`, and `ts-morph` so every hit resolves `symbol_identity -> source_revision -> candidate_id -> qdrant_point_id`.

### P3 — Recommendation Engine, Agentic Error Fixing & Offline Training (Target: 100%)

3. **Agentic Error Fixing**: Enforce `verifiedClaim -> KernelDagCandidate -> schema/lineage/auth admission -> bounded execution -> independent readback` (`PUCT` scoring in `duckdb_bytea_rpc_packet_v1.py`).

## Retrieval and learning alignment notes — 2026-11-24

- **Fresh source candidate is not admission:** The local snapshot candidate contains 32,708 source records / 6 repositories, but the subsequent derivation found 2 post-capture byte changes (`docs/graph/contract-error-map.json` and `sveltekit-frontend/src/routes/api/atlas/hypergraph/vertex-stream/+server.ts`), leaving 32,706 exact matches and `SNAPSHOT_READBACK_NOT_PROVEN`. Its workspace revision is null and it has no canonical authority. The current-frame audit still reports zero current matches; structural Graphify reports zero nodes/edges and no graph revision. Stabilize and recapture before any existing source-index/Graphify admission; do not turn this local snapshot into production source authority.
- **Stable recapture and admission preflight:** A second snapshot candidate passed exact byte readback (32,708/32,708), generated a deterministic workspace-revision candidate, passed source inventory hygiene (32,486 selected sources), and produced a matching `SOURCE_SELECTION_PLAN_READY_NOT_ADMITTED` Graphify plan. The final authority preflight passed all source, plan, inventory, and exclusion checks; its sole blocker is that the manifest remains in `.tmp/atlas` rather than the canonical snapshot admission directory. Keep it noncanonical until the operator admission owner publishes it. Existing frame and structural graph audits still show no current admitted source cohort or graph edges.
- **Agentic dense search:** Keep exact identifier/symbol lookup and lexical retrieval as independent candidate lanes; use AST/CST symbol, path, and parent context for code chunks; treat full-encoder EG2 semantic retrieval as a separate lane; then add bounded, admitted graph expansion. SearchRuntime remains the single cross-lane normalization/RRF owner. Avoid repeated `top 1 → 10 → 100 → 1,000` expansions per request. Start with one measured bounded pool per lane (for example, 100), retain stable candidate ordinals, merge once, and paginate the final order with a stable cursor. Measure Recall@10, MRR, nDCG@10, citation precision, and p95 before changing pool sizes.
- **Candidate funnel:** A coarse-to-fine `1,000 → 100 → 10 → 1` funnel is a budget pattern, not repeated independent searches: retrieve one bounded wide pool; apply eligibility/symbol/domain features without hard-dropping low-confidence domains; fuse lanes once; rerank to a small evidence set; let ACE select a supported answer with its citations. If recall at the wide stage is poor, later stages cannot recover the missing source.
- **Graph meaning:** HNSW is an approximate vector-neighbor index; it does not encode `CALLS`, `IMPORTS`, ontology predicates, or evidence. Keep typed, revision-bound graph traversal separate and rejoin results to PostgreSQL before ACE.
- **Ranking roles:** cuVS/CAGRA is an ANN candidate-generation challenger; cuGraph PageRank can reorder nodes already reached through admitted, revision-matched graph edges; cuML KMeans/SOM and domain predictions are exploratory grouping/ranking features. None creates a graph relation, authority, or additional SearchRuntime vote. The live `:8098` route currently proves cuGraph PageRank capability only; its residency is empty and CAGRA is not exposed by its OpenAPI.
- **Learning boundaries:** MLP backprop is offline supervised ranking over reviewed candidate labels/features. Cosine is a retrieval metric or feature, not a gold label or self-generated reward. QLoRA adapts generation behavior; it does not align vector spaces and cannot replace MLP ranking labels. Neither can promote itself.
- **RAPIDS transport:** Reuse the existing GPU executor contract and CPU oracle. A WSL2-to-Windows RPC is needed only if the selected process boundary requires it; regardless, the input cohort must be frozen and revision-qualified, GPU resource admission must pass, CPU/GPU parity must be measured, and returned ordinals must rejoin exactly. cuGraph/cuML remain challengers until those gates pass. TensorRT-RTX stays low priority until a measured workload shows a bottleneck it can address.
- **Embedding recipe:** Google documents an 8,192-token EG2 context limit. Honor that in the application even if a local GGUF reports a larger internal window. Every benchmark/index receipt should bind the installed Ollama model digest, source GGUF checksum where available, query/document prompt revision, normalization behavior, dimension, and corpus/query checksums. The existing 1K MRL report alone does not prove a production encoder migration.
- **Versioned challenger storage:** `codebase_chunk_eg2_embeddings` uses `source_id` as its primary key, so it cannot retain two prompt/model recipes for one source chunk. The updated builder refuses unqualified legacy rows and labels the new full-768 code-retrieval recipe; add a reviewed, additive versioned storage contract before running a new batch. Do not delete or overwrite existing challenger rows as a shortcut.
- **Domain classifier:** A live float32/float64 mismatch in sklearn KMeans inference is fixed in the shared feature helper. The current HTTP route and a fresh in-container call both execute the checkpoint as `sklearn-lr`, `SHADOW_ONLY`; runtime module hashes match the mounted checkout. The synthetic auth/database example predicts `ui` (LR probability about 0.549), exposing a quality failure. The checkpoint still warns about sklearn 1.7.0 artifact vs 1.7.2 runtime. Keep predictions advisory until version reconciliation and reviewed, source-grouped evaluation pass.
- **Docs corpus policy:** The supplied size audit says JSON/JSONL artifacts dominate `docs/` while Markdown is about 46 MiB. Treat prose, authoritative manifests, generated receipts, large dumps, and temp/backup artifacts as separate source classes. Index selected, revision-qualified documents; exclude generated reports/dumps from default retrieval unless a query explicitly targets audit evidence. Preserve source IDs and exact spans regardless of whether the transport is ACE JSON or PFB1/ARPC binary.
