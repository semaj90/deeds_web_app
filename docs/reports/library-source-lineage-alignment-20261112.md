## What was wrong in the pasted implementation sketch

The proposed authorization SQL names columns and relationships that this repository's owner schema does not define. `library_documents` has `uploaded_by` as an integer and `source_hash`; it has no `uploaded_by_user_id`, `case_id`, `source_sha256`, or `current_revision_id`. The app now models `library_document_versions.source_hash`, but the base DDL did not include it, so the candidate sidecar adds it without inventing values for legacy rows. A query joining `cases.owner_user_id` from `library_documents.case_id` still cannot be used; case linkage belongs to `case_library_links`.

The existing `library-document-access-v1.ts` helper instead follows the current policy: `uploaded_by IS NULL` means shared corpus, otherwise only the matching integer uploader may access it. It optionally checks case access separately, but that does not establish that a library document belongs to the case.

## Current route alignment

- **PDF read:** The current uncommitted route calls `authorizeLibraryDocumentV1` before metadata lookup and SeaweedFS access, then rejects non-PDF MIME types. Denial is a non-disclosing 404.
- **Library search:** A supplied document ID is checked before analytics, embedding, or search; a denied document now returns a non-disclosing 404 with an empty, stable response shape. Inline PostgreSQL queries include shared-or-uploader visibility in the SQL. The Go shortcut is now fail-closed behind a constant set to `false`; it remains unavailable until the Go executor proves visibility filtering before retrieval and scoring. The previous unscoped total is replaced by visible hit count as defense in depth.
- **Synthesis:** The current route authorizes `caseId` before cache/model work. It does not accept a document scope or bind retrieved context and cache keys to `documentId`, `source_hash`, and a version. Case authorization alone is not document-lineage proof.
- **Upload:** Browser library pages send the `File` directly as the request body, selecting the raw bounded stream path; the route verifies declared length, hashes incrementally, and checks file signatures before forwarding bytes to SeaweedFS. Multipart compatibility requires a valid `Content-Length` and rejects requests above 201 MiB before calling `Request.formData()`; parsing still buffers within that bound. Optional `caseId` authorization happens before the raw body is consumed; document/version/case-link/job records are committed together.
- **Queue:** The worker claims jobs with `FOR UPDATE SKIP LOCKED`, lease tokens, bounded attempts, and retry scheduling. It now requires an enqueue-time SHA-256 and compares it with the document's current source hash before extraction. Re-ingestion APIs enqueue work instead of starting an in-process promise. These paths require the candidate lease and source-binding migrations, which are not applied or live-proven.
- **Stage lineage:** New jobs and document-version rows carry nullable `source_hash` columns. The draft migration deliberately leaves legacy rows NULL; the queue will not claim unqualified legacy jobs. Document/version/job creation is transactional through Drizzle, but there is still no per-stage receipt chain for extraction/OCR/chunk/embed outputs.
- **Search naming:** The route used analytics pipeline label `kag` even though its inline path is PostgreSQL `ts_rank` plus weighted linear cosine fusion (0.4/0.6), not BM25 or RRF. Analytics now records `library-search`; inline responses identify the actual lexical or weighted-hybrid method in `meta`. Empty/error responses retain the same top-level `hits`, `results`, `total`, and `meta` keys.
