# Workspace Feature and Storage Master Register

**Status:** READ-ONLY INVENTORY / REVIEW REQUIRED
**As of:** 2026-11-01
**Authority:** This report is a crosswalk proposal, not a canonical registry, migration receipt, archive approval, or production-readiness claim.

## Purpose

Create one review surface for feature labels, domain/taxonomy classification, embedding/index evidence, runtime environment, and repository-artifact disposition. Keep Legal AI application state, Parent Atlas authority, and workstation-only experiments separate. A filename, registry row, Qdrant point, cluster assignment, or model proposal is not by itself canonical identity or proof of production use.

## Master-register fields

Each eventual row should preserve these fields and their evidence separately:

| Field | Meaning / evidence rule |
| --- | --- |
| `feature_id` | Existing registered ID only; never derive it from a label or path. |
| `feature_label` | Exact persisted label, with source table and row identity. A registry `title` is only a proposed display label until joined. |
| `domain_id`, `taxonomy_id`, `classification_status` | Exact registered domain and taxonomy revision; distinguish proposal, classified, reviewed, and admitted. |
| `source_ref`, `source_revision`, `workspace_revision`, `content_digest` | Immutable source lineage. Missing bindings keep the row unqualified. |
| `embedding_model`, `representation`, `dimensions`, `embedding_revision`, `embedded_status` | Record actual EmbeddingGemma `semantic_768` separately from derived MRL/latent representations. Require the row identity and revision. |
| `canonical_store`, `indexed_status`, `index_revision`, `index_readback` | PostgreSQL is canonical; Qdrant/graph/GPU indexes are projections. Record exact readback, not just a point ID or `indexed_at`. |
| `cluster_model_revision`, `cluster_id`, `topk_role` | Derived routing metadata only; never canonical identity or a second retrieval vote. |
| `runtime_owner`, `environment_lane` | `legal-ai-app`, `parent-atlas`, or `workstation`; plus `production`, `development`, `test`, `evaluation`, or `archive-candidate`, each evidence-backed. |
| `artifact_owner`, `created_at`, `checksum`, `reproducible`, `consumer_refs`, `disposition` | Required before consolidation: retain, archive-candidate, regenerate-candidate, or unresolved. No deletion implied. |

Unknown fields remain `UNVERIFIED`; do not fill them from names, timestamps, generated summaries, or heuristics. Proposed label/domain mapping must not be written back to canonical stores until separately admitted.

## Evidence synthesis contract implementation

The first pure-contract slice is implemented in `sveltekit-frontend/src/lib/server/evidence/synthesis/evidence-claim-v1.ts`. Zod schemas separate extractor proposals from grounded claims; the grounding helper checks source/case/workspace revision bindings, verifies the SHA-256 over the supplied original bytes, validates exact Unicode text spans, computes UTF-8 byte offsets itself, and only advances `PROPOSED` to `SOURCE_GROUNDED`. A typed LangExtract-fact adapter preserves source URL, producer/model/output digest, extraction method, confidence, and product revision, and rejects non-exact alignment or mismatched offsets. It has no database, queue, network, or model side effects. Focused Vitest: 8/8 passed; focused ESLint: exit 0; `npx openspec validate parent-atlas-evidence-agent-proposals --strict`: exit 0. This proves only the pure contract/adapter—not a live upload/8095 call, model-backed summary, taxonomy mapping, or persistence path. The matching OpenSpec contract/conversion tasks are checked; worker integration and later agent workflows remain open.
