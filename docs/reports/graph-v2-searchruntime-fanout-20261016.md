## Bounded GraphV2 multi-hop traversal (2026-10-17)

The existing GraphV2 SQL reader is a strict one-hop query. SearchRuntime now routes it through `executeGraphV2BoundedTraversalV1`, which performs up to three breadth-first hops with a 64-candidate/frontier ceiling and at most four concurrent one-seed reads. One-seed reads are intentional: the existing SQL result does not identify which input seed produced each hit, so batching several parents would make relation-path attribution ambiguous. The coordinator pins the same workspace and graph revisions at every hop, rejects malformed readback, terminates cycles by exact packet/source/source-revision identity, multiplies relation confidence along the path, and carries the complete relation-ID path into existing `graphEvidenceRefs` for final-packet/ACE qualification. It adds no table, graph writer, RRF vote, or canonical data mutation.

A SearchRuntime fixture confirms that a two-hop relation path reaches hydration and final Top-K, and that both relation IDs appear in graph provenance only for the exact revision-matched final packet. This is code/fixture proof only.
