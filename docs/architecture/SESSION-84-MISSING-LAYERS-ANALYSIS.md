# Session 84 — Missing Architectural Layers Analysis

**Date**: June 27, 2026  
**Status**: Critical gaps identified | Derived artifact registry is blocking all downstream  
**Impact**: Without artifact registry + semantic diff, we cannot close the loop on regeneration

---

## Problem Summary

We have built a **retrieval-centric** system:
- ✅ Packet identity (frozen)
- ✅ BitFrost cache (working)
- ✅ Feature labels (working)
- ✅ GAN validation gates (working)
- ✅ GPU acceleration (working)
- ✅ Telemetry (working)

But we're missing the **generative feedback loop**:
- ❌ No registry of derived artifacts
- ❌ No semantic diff (when to regenerate)
- ❌ No artifact lineage (what was generated from what)
- ❌ No replay database (what happened in production)
- ❌ No reward dataset (feedback for fine-tuning)

**Result**: Regeneration is manual, not automated. Cache is write-once, not learned.

## Layer 1: Derived Artifact Registry (CRITICAL PATH)

### Current Problem
```
atlas_packets (17,995 rows)
  ↓
  ├─ summary (generated by Gemma4, stored nowhere)
  ├─ embedding (generated by EmbeddingGemma, stored in Qdrant only)
  ├─ latent64 (generated by AE, stored nowhere)
  ├─ som_cell (generated by SOM, stored in metadata)
  ├─ qdrant_payload (mirrored, no lineage)
  ├─ redis_cache (ephemeral, no history)
  ├─ karpathy_blend (computed, stored in Redis only)
  ├─ markdown (generated as file, not tracked)
  └─ documentation (generated as file, not tracked)

Nobody knows:
  - Which generator created what (version tracking)
  - What packet_key led to what artifact
  - When artifacts are stale (git_commit metadata)
  - Whether regeneration is needed (content_hash)
  - What lineage led to GAN success/failure
```

### Solution: `atlas_artifacts` Table

```sql
CREATE TABLE atlas_artifacts (
  artifact_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  packet_key VARCHAR(255) NOT NULL,                    -- FK to atlas_packets
  feature_id VARCHAR(255) NOT NULL,                    -- Denorm for queries
  artifact_type VARCHAR(50) NOT NULL,                  -- summary|embedding|latent64|som_cell|qdrant_payload|redis_cache|markdown|documentation|karpathy_tags|gpu_projection|gemma4_prompt
  
  -- Content & Hashing
  content_hash VARCHAR(64),                            -- SHA256 of artifact
  content_hash_algorithm VARCHAR(20) DEFAULT 'sha256',
  
  -- Generator Tracking (FOR REPRODUCIBILITY)
  generator VARCHAR(100) NOT NULL,                     -- Gemma4|EmbeddingGemma|AutoEncoderModel|SOMClusterer|RedisWriter|MarkdownGenerator
  generator_version VARCHAR(20) NOT NULL,              -- e.g., "gemma4-legal-iq4xs", "embeddinggemma:latest"
  generator_config JSONB,                              -- temperature, max_tokens, model_params, etc.
  
  -- Lineage & Reproducibility
  git_commit VARCHAR(40),                              -- git SHA at generation time
  source_packet_hash VARCHAR(64),                      -- SHA256 of source packet at generation time
  depends_on_artifacts UUID[],                         -- IDs of artifacts that fed this one
  supersedes_artifact_id UUID,                         -- If this replaces a prior artifact
  
  -- Validation
  gan_validated BOOLEAN DEFAULT false,
  gan_validation_score REAL,
  gan_validation_error TEXT,
  
  -- Storage Location
  storage_location VARCHAR(500),                       -- file path, Qdrant point_id, Redis key, etc.
  storage_backend VARCHAR(50),                         -- filesystem|qdrant|redis|postgres_jsonb|seaweedfs
  
  -- Metadata
  artifact_metadata JSONB,                             -- artifact-specific metadata
  tags TEXT[],                                         -- for filtering & discovery
  
  -- Audit Trail
  created_at TIMESTAMP DEFAULT NOW(),
  created_by VARCHAR(100),                             -- Gemma4|GAN validator|batch job
  updated_at TIMESTAMP DEFAULT NOW(),
  updated_by VARCHAR(100),
  
  -- Indexing
  FOREIGN KEY (packet_key) REFERENCES atlas_packets(packet_key),
  INDEX idx_artifact_packet (packet_key),
  INDEX idx_artifact_type (artifact_type),
  INDEX idx_artifact_generator (generator, generator_version),
  INDEX idx_artifact_git_commit (git_commit),
  INDEX idx_artifact_hash (content_hash),
  INDEX idx_artifact_created (created_at)
);

-- Lineage view: trace any artifact back to source
CREATE VIEW artifact_lineage AS
WITH RECURSIVE lineage AS (
  SELECT artifact_id, packet_key, generator, 1 as depth
  FROM atlas_artifacts
  WHERE artifact_type = 'summary'  -- Start from summaries
  
  UNION ALL
  
  SELECT a.artifact_id, a.packet_key, a.generator, l.depth + 1
  FROM atlas_artifacts a
  JOIN lineage l ON a.artifact_id = ANY(l.depends_on_artifacts)
  WHERE l.depth < 10  -- Prevent cycles
)
SELECT * FROM lineage;
```

### Why This Matters

**Before** (current):
- Regenerate everything (expensive)
- No way to know if regeneration succeeded
- No feedback loop for fine-tuning
- Cache hits are magical, not learned

**After** (with registry):
- Know exactly what was generated when
- Trace GAN success/failure back to generator
- Feed successful artifacts into training data
- Learned routing: "Gemma4 v1 failed on this packet type, use v2"

## Layer 2: Semantic Diff (GATES REGENERATION)

### Current Problem
```
Source code changed
  ↓
git diff detects text change
  ↓
Mark packet SUPERSEDED
  ↓
Regenerate everything
  ↓
(Probably 90% of regenerations are unnecessary)
```

### Solution: Compare Embeddings, Not Text

```typescript
// src/lib/server/semantic-diff/semantic-diff.ts

interface SemanticDiffResult {
  similarity: number;              // 0.0 to 1.0
  recommendation: 'skip' | 'partial' | 'full';
  confidence: number;
}

async function semanticDiff(
  oldPacket: Packet,
  newPacket: Packet,
  oldEmbedding: Float32Array,    // Cached from Qdrant
  newEmbedding: Float32Array,    // Just computed
): Promise<SemanticDiffResult> {
  // 1. Cosine similarity between embeddings
  const similarity = cosineSimilarity(oldEmbedding, newEmbedding);
  
  // 2. Thresholds (tunable)
  if (similarity >= 0.98) {
    return { similarity, recommendation: 'skip', confidence: 0.95 };
  }
  if (similarity >= 0.85) {
    return { similarity, recommendation: 'partial', confidence: 0.80 };
  }
  return { similarity, recommendation: 'full', confidence: 0.90 };
}

// Usage in git-diff reconciliation
for (const changedFile of changedFiles) {
  const oldPacket = await getPacketFromPostgres(changedFile);
  const newPacket = await parsePacketFromSource(changedFile);
  
  const oldEmbedding = await getEmbeddingFromQdrant(oldPacket.packet_key);
  const newEmbedding = await embedText(newPacket.summary);
  
  const diff = await semanticDiff(oldPacket, newPacket, oldEmbedding, newEmbedding);
  
  if (diff.recommendation === 'skip') {
    console.log(`✅ Skip regeneration (${diff.similarity.toFixed(3)} similarity)`);
    continue;  // Don't regenerate
  }
  
  if (diff.recommendation === 'partial') {
    console.log(`⚠️  Partial update (${diff.similarity.toFixed(3)} similarity)`);
    await updateSummaryOnly(oldPacket);  // Faster than full regeneration
    continue;
  }
  
  console.log(`🔄 Full regeneration (${diff.similarity.toFixed(3)} similarity)`);
  await fullRegeneration(oldPacket);
}
```

### Artifact of Semantic Diff

Every semantic diff becomes a **record**:
```
atlas_semantic_diffs
  diff_id UUID
  old_artifact_id UUID
  new_artifact_id UUID (or NULL if skipped)
  similarity REAL
  recommendation TEXT
  action_taken TEXT
  regeneration_cost_saved REAL
  created_at TIMESTAMP
```

**Benefits**:
- Skip 80-90% of unnecessary regenerations
- Learn which thresholds are correct
- Feedback: "When similarity was 0.87, regeneration was worth it 95% of the time"

## Layer 3: Artifact Lineage Graph (REPRODUCIBILITY)

### Problem: Where Did This Artifact Come From?

```
User: "Why is this summary wrong?"
Me: "Gemma4 generated it from packet auth.ts"
User: "What was the prompt?"
Me: "I don't know, we didn't store it"
User: "Can we regenerate with a different model?"
Me: "I don't have the source packet from that time"
```

### Solution: Full Lineage Tracking

```
artifact_lineage_edges (in Neo4j or Postgres)
  edge_id UUID
  source_artifact_id UUID      -- e.g., summary artifact
  target_artifact_id UUID      -- e.g., embedding artifact
  edge_type TEXT               -- 'generated_from', 'cached_from', 'regenerated_from'
  
  generator VARCHAR(100)       -- Which system created this edge
  created_at TIMESTAMP
  git_commit VARCHAR(40)       -- For debugging "why was this path taken?"
```

**Neo4j Graph**:
```
(:Packet {packet_key: 'ace:packet:auth:001'})
  -[:PRODUCED_BY {generator: 'Gemma4', time: '2026-06-27T...'}]->
    (:Artifact {type: 'summary', content_hash: '...'})
      -[:VECTORIZED_BY {generator: 'EmbeddingGemma'}]->
        (:Artifact {type: 'embedding', qdrant_point_id: '...'})
          -[:COMPRESSED_BY {generator: 'AutoEncoder'}]->
            (:Artifact {type: 'latent64', storage: 'redis'})
              -[:MATERIALIZED_BY {generator: 'KarpathyBlender'}]->
                (:CacheKey {key: 'centroid:feature:auth.sessions'})
```

**Query**: "Show me why GAN validation failed on this packet"
```cypher
MATCH (p:Packet {packet_key: 'ace:packet:auth:001'})
  -[:PRODUCED_BY {generator: $failedGenerator}]->(a:Artifact)
  -[path*..5]->(:CacheKey)
RETURN path, COLLECT(nodes) as lineage
```

## Layer 4: Replay Database (PRODUCTION GROUND TRUTH)

### Problem: Optimize What You Can Measure

Currently: We generate summaries. We don't know if they're useful.

Solution: **Record every production use**, then replay to measure value.

```sql
CREATE TABLE agent_runs (
  trace_id UUID PRIMARY KEY,
  timestamp TIMESTAMP,
  
  -- Input
  user_prompt TEXT,
  user_id VARCHAR(100),
  
  -- Retrieval
  retrieved_packet_ids UUID[],           -- Which packets were used
  retrieval_strategy VARCHAR(50),        -- 'cache_hit' | 'qdrant' | 'neo4j' | 'fallback'
  retrieval_latency_ms INT,
  
  -- ACP Planning
  acp_decisions JSONB,                   -- Router logic, routing matrix scores
  
  -- MCP Tools
  mcp_tools_called VARCHAR(100)[],
  mcp_tool_results JSONB[],
  
  -- Generation
  llm_model VARCHAR(50),                 -- Gemma4 version
  llm_prompt TEXT,                       -- Full prompt sent to LLM
  llm_output TEXT,                       -- Full LLM response
  llm_latency_ms INT,
  llm_input_tokens INT,
  llm_output_tokens INT,
  
  -- Artifacts Generated
  generated_artifact_ids UUID[],         -- IDs of all artifacts produced
  
  -- Validation
  gan_score REAL,
  gan_passed BOOLEAN,
  
  -- Performance
  cache_hits INT,
  cache_misses INT,
  total_latency_ms INT,
  gpu_vram_mb INT,
  cpu_percent REAL,
  
  -- User Feedback (eventual)
  user_accepted BOOLEAN,
  user_regenerate_requested BOOLEAN,
  user_feedback_text TEXT,
  
  -- Audit
  success BOOLEAN,
  error_message TEXT,
  error_type VARCHAR(50),
  
  INDEX idx_trace_timestamp (timestamp),
  INDEX idx_trace_user (user_id),
  INDEX idx_trace_model (llm_model),
  INDEX idx_trace_success (success)
);
```

### Why This Matters

**Before**: "Gemma4 is slow, but I don't know when or why"

**After**: Query replay database:
```sql
-- Which packets are slowest to generate?
SELECT packet_key, AVG(total_latency_ms) as avg_latency, COUNT(*) as runs
FROM agent_runs, UNNEST(retrieved_packet_ids) as pid
GROUP BY packet_key
ORDER BY avg_latency DESC
LIMIT 20;

-- Which retrieval strategy works best for legal queries?
SELECT retrieval_strategy, 
       COUNT(CASE WHEN user_accepted THEN 1 END) * 100.0 / COUNT(*) as acceptance_rate,
       AVG(total_latency_ms) as avg_latency
FROM agent_runs
WHERE user_prompt ILIKE '%patent%' OR user_prompt ILIKE '%statute%'
GROUP BY retrieval_strategy;

-- Which artifacts are reused most?
SELECT artifact_id, COUNT(*) as uses, SUM(cache_hits) as total_hits
FROM agent_runs, UNNEST(generated_artifact_ids) as aid
GROUP BY artifact_id
ORDER BY uses DESC;
```

## Layer 5: Reward Dataset (FOUNDATION FOR FINE-TUNING)

### Problem: How Do We Know Regeneration Was Worth It?

```
Generated file from Packet X
  ↓
Tests pass?  ✅ +1 point
  ↓
Linter happy?  ✅ +1 point
  ↓
User accepted?  ✅ +2 points
  ↓
Total reward: +4 (out of 8)

↓ Store this as training data
```

### Schema

```sql
CREATE TABLE artifact_rewards (
  reward_id UUID PRIMARY KEY,
  
  -- What was evaluated
  artifact_id UUID NOT NULL,
  artifact_type VARCHAR(50),
  generator VARCHAR(100),
  generator_version VARCHAR(20),
  
  -- Reward signal (can be multiple)
  reward_dimension VARCHAR(50),          -- 'compilation' | 'tests' | 'lint' | 'user_acceptance' | 'performance' | 'security'
  reward_score REAL,                     -- -1.0 to +1.0
  reward_metadata JSONB,                 -- e.g., {"test_failed": "line 42", "test_name": "..."}
  
  -- Context
  packet_id UUID,
  context_before TEXT,                   -- Code context before change
  context_after TEXT,                    -- Generated code
  git_commit VARCHAR(40),
  
  -- User feedback (highest quality signal)
  user_accepted BOOLEAN,
  user_feedback_text TEXT,
  user_feedback_score REAL,              -- How confident is the user?
  
  -- Timing
  created_at TIMESTAMP,
  
  INDEX idx_reward_artifact (artifact_id),
  INDEX idx_reward_generator (generator, generator_version),
  INDEX idx_reward_dimension (reward_dimension)
);
```

### Export for QLoRA Training

```sql
-- Export successful artifacts for fine-tuning
SELECT 
  a.generator,
  a.generator_config,
  a.artifact_metadata->>'llm_prompt' as prompt,
  a.content_hash,  -- Or actual content from storage
  ar.reward_score,
  ar.reward_dimension,
  ar.context_before,
  ar.context_after,
  ar.user_accepted
FROM atlas_artifacts a
JOIN artifact_rewards ar ON a.artifact_id = ar.artifact_id
WHERE ar.reward_score > 0.7  -- Only good examples
  AND a.generator = 'Gemma4'
  AND a.created_at > NOW() - INTERVAL '7 days'
ORDER BY ar.reward_score DESC;
```
