## CPU, GPU, and inference lane alignment

- **Host SIMD:** this workstation reports an Intel Core i7-11700F (8 cores / 16 threads); Intel lists AVX2 and AVX-512 support for this SKU. SIMDJSON/N-API parsing is CPU work. Runtime dispatch/build flags and throughput still require a native probe; CPU AVX2 is not CUDA SIMT.
- **GPU execution:** CUDA SIMT kernels, cuTile tile kernels, LibTorch/ATen, cuBLASLt, cuVS/CAGRA, and cuGraph are distinct executors. Keep the existing CUDA 13.2 cuTile experiment and CUDA 13.4 SIMT/Tile container separate; both remain challengers until same-input CPU parity, numerical tolerance, resource, and timing receipts pass.
- **Retrieval:** TurboVec is a candidate-search/prefilter executor, not an embedding or identity owner. PostgreSQL remains canonical for qualified `semantic_768`; Qdrant, TurboVec, and cuVS/CAGRA must normalize into one SearchRuntime semantic lane and one fusion vote. Compare ANN results with exact KNN ground truth.
- **LLM inference and KV:** TensorRT-LLM/Triton serving, TensorRT for RTX engine execution, and the app's KV-compression interfaces are separate runtime paths. QLoRA weights are adapter parameters, PTX is kernel code, and KV cache is inference state; none is interchangeable. The `kv-compression-backend-v1` FP16 passthrough contract is not proof of the llama-server's live KV-cache implementation. Do not co-schedule training, graph/vector GPU work, or another inference owner without an explicit GPU lease.
- **ACE namespacing:** Parent Atlas ACE means Agent Context/packet/context assembly. NVIDIA cuVS ACE means Augmented Core Extraction for partitioned HNSW construction. Keep distinct identifiers, schemas, and receipts; neither implies the other ran.
- **Representation manifest gap:** `PacketRepresentationManifestV1` binds packet/source/workspace revisions, representation/artifact checksums, codec, dtype, shape, and executor allowlist. It does not yet bind the embedding recipe/normalization, cluster-model revision, or ordinal-map checksum needed for the proposed frozen tournament input. Do not treat it as that complete manifest or make a parallel canonical registry; extend the existing contract only through its owning change.

## Rules

- **SIMDJSON boundary**: parses/validates JSON and extracts typed values. It does not perform graph traversal, sparse-tree propagation, taxonomy resolution, or GPU work. `from_blob` can avoid an intermediate host copy, but `.to(cuda)` is a host-to-device transfer; do not describe this path as end-to-end zero-copy or assume Tensor Core execution from `torch::mm` alone.
- **Graph and hypergraph boundary**: `atlas_graph_networkx_mirror_v1.py` preserves directed edges in a revision/checksum-bound `MultiDiGraph`; `nary_networkx_alignment_v1.py` builds role-separated incidence/CSR from admitted proposal envelopes. These are derived analysis projections; canonical participant resolution, `.okf` corpus admission, and GPU parity remain separate gates.
- **cuVS/cuGraph boundary**: cuVS/CAGRA searches vectors; cuGraph runs graph algorithms on a supplied graph projection. A CAGRA neighbor edge is not a canonical `CALLS`/ontology relation. Community algorithms that require undirected input must use a separately declared projection and must not overwrite directed source edges.
- **Taxonomy/ontology alignment**: terms and IDs resolve through existing PostgreSQL/OAK owners. Keyword clusters, topics, classifier labels, PageRank, and communities are features/proposals only; they cannot mint canonical entities, ontology predicates, revisions, or additional retrieval votes.
- **Glossary crosswalk**: keep raw terms, normalized aliases, language, corpus/source revision, glossary revision, match method, and evidence span together. `EXACT`, `AMBIGUOUS`, `UNMAPPED`, and owner-resolved outcomes are distinct; do not promote keyword similarity into an ontology fact. See [`_taxonomy_oak_graphrag_index.md`](./_taxonomy_oak_graphrag_index.md).

- GEMM performance comparisons use `atlas_cuda_cutile_simt_gemm_probe_v1.py`; do not add a second GEMM owner.
- Do not run any cuTile or CUDA job while `:8090` (Ornith) is loaded; free it through the documented task first.
- cuTile is a challenger lane. It does not replace cuBLASLt, cuVS, or LibTorch ownership.
- GPU admission (VRAM budget, CPU parity, receipt) is required before any deployment.
- **LibTorch CPU Parameter Fetching**: Host parameter tensors fetched for CPU execution or inspection must wrap existing memory via `torch::from_blob` specifying explicit dimensions and options. Output copies must write to pre-allocated typed arrays to prevent dynamic heap re-allocation in hot loops.
- **LUT Boundary**: LUT ordinals and byte codes (`PacketClassLutV1`, `CandidateOrdinalMapV1`) are presentation projections for token caching and GEMM indexing; they must never substitute for canonical UUIDs or database primary keys.
- **ACP / A2A Non-Canonical Rule**: ACP and A2A loops orchestrate tasks and parameter routing; they must never mutate PostgreSQL, Qdrant, or Neo4j directly without schema/lineage authorization receipts.
- **torch.from_file & MMap Tensor Boundary (TENSOR-MMAP-01)**:
  `torch.from_file(filename, shared=False, size=N*dim, dtype=torch.float32)` maps a contiguous row-major binary file (`.f32bin`) directly into CPU virtual address space without heap copying.
  1. *CPU Only*: Memory-mapped storages are host-only (`device=torch.device('cpu')`). They cannot be created directly in CUDA VRAM.
  2. *No Pinned Memory*: PyTorch strictly forbids file-backed storage in pinned memory (`pin_memory=False` enforced). Asynchronous CUDA DMA requires gathering candidate rows into a pinned staging buffer first.
  3. *Immutability Guardrail*: Frozen canonical matrices must always specify `shared=False` (`MAP_PRIVATE` copy-on-write) to guarantee `writes: 0` against on-disk snapshots.
  4. *Selective Gather*: Never transfer the entire mmap corpus to GPU. Gather bounded candidate ordinals ($K \ll N$) via `mmap_tensor.index_select(0, candidate_ordinals)` and DMA-transfer only the $[K, \text{dim}]$ slice to CUDA for GEMM or attention rescoring.
