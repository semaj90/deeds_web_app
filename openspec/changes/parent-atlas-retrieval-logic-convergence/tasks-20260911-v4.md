## Identity correction discovered before live execution

`ChunkRetrievalProfileV1` constrained `canonicalChunkId` to UUID. That is
incorrect for the frozen packet/chunk lineage contract.

The canonical lineage schema establishes:

- `atlas_packet_chunk_lineage.canonical_chunk_id` = TEXT copied from existing
  `codebase_chunk_index.chunk_id`;
- `atlas_packet_chunk_lineage.chunk_row_id` = UUID physical row identity from
  `codebase_chunk_index.id`;
- canonical chunk identity must never be minted from random UUID, source path,
  tree node, Qdrant point ID, or nearest-match inference.

Therefore V1 is retained as historical evidence but is superseded for new
hydration/readback by:

- `chunk-retrieval-profile-v2.ts`
- `chunk-retrieval-profile-adapter-v2.ts`
- `chunk-retrieval-profile-v2.spec.ts`

V2 carries both identity grains explicitly:

```text
canonicalChunkId : text  // codebase_chunk_index.chunk_id
chunkRowId       : uuid  // codebase_chunk_index.id
```

No V1 file was rewritten to conceal this correction.

## Fail-closed rules

The live readback reports a blocker rather than fabricating data when any bounded
row lacks:

- canonical chunk / physical chunk row / packet identity;
- repository-qualified source identity;
- workspace/source revision;
- feature revision;
- evidence refs;
- at least one existing feature group.

The audit performs a `REPEATABLE READ READ ONLY` PostgreSQL transaction and
reports:

```text
writesPerformed = false
canonicalAuthorityChanged = false
```

It performs no Qdrant, Neo4j, Valkey, Graphify, model, or container mutation.
