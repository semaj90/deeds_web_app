## Proof semantics

The replay deliberately permutes only fields whose V2 contract semantics are
set-like:

```text
keywords
identifiers
nouns
calls
imports
exports
semanticTags
topicIds
conceptIds
entityIds
ontologyTupleIds
evidenceRefs
```

`astPath` is never permuted because path order carries structural meaning.

A successful bounded replay requires, for every selected row:

```text
baselineChecksum == permutedChecksum
canonical identity unchanged
featureRevision missing  -> rejected
workspaceRevision missing -> rejected
sourceRevision missing -> rejected
evidenceRefs empty -> rejected
```

The only forward status is:

```text
PROFILE_LIVE_REPLAY_PROVEN
```

Any discrepancy yields:

```text
PROFILE_LIVE_REPLAY_BLOCKED
```

with typed blockers such as:

```text
CHECKSUM_ORDER_DEPENDENT
IDENTITY_CHANGED_DURING_REPLAY
MISSING_FEATURE_REVISION_ACCEPTED
MISSING_WORKSPACE_REVISION_ACCEPTED
MISSING_SOURCE_REVISION_ACCEPTED
MISSING_EVIDENCE_REFS_ACCEPTED
ROW_HYDRATION_FAILED
```
