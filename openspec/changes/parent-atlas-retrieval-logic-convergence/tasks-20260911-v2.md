## Temporal append-only rule

Historical task ledgers and proof artifacts are immutable evidence once written.
Do not rewrite a whole ledger to reflect a later understanding when a temporal
addendum can preserve both states.

For future changes to this workstream:

1. append a dated temporal addendum when only status/order/evidence changed;
2. create a `v2`/`vNext` contract or artifact when semantics changed;
3. mark older claims as historical/superseded rather than deleting them;
4. never infer that a newer addendum invalidates old proof unless it explicitly
   names the superseded claim and explains why;
5. avoid whole-file replacement of large append-only ledgers through APIs that
   cannot safely patch/append; create a companion/addendum file instead;
6. code files may still be updated normally when implementation changes are
   intentional and reviewable; the append-only rule applies to evidence/task
   history, receipts, and frozen contracts whose chronology matters.

### RETRIEVAL-PROFILE-01 — contract

- [x] Added
  `sveltekit-frontend/src/lib/server/atlas/retrieval/chunk-retrieval-profile-v1.ts`.
- [x] Contract binds canonical chunk/packet/source identity to optional
  lexical/structural, semantic, domain/topic, topology, and ontology feature
  groups.
- [x] Required revision-qualified identity includes:
  `canonicalChunkId`, `packetKey`, `repositoryId`,
  `repositoryRelativePath`, `sourceIdentityKey`, `sourceRef`,
  `workspaceRevision`, and `sourceRevision`.
- [x] `sourceIdentityKey` is validated as
  `repositoryId:normalizedRepositoryRelativePath`; no Qdrant point ID, array
  index, basename, or executor-local ID can substitute for it.
- [x] Repository-relative paths reject absolute/traversal-bearing paths.
- [x] At least one feature/evidence group must be present; the contract cannot
  fabricate an empty feature profile.
- [x] Semantic group is fixed to `embeddingRepresentation: semantic_768` and
  records representation/model revision only; raw vectors stay outside the
  profile.
- [x] Topology group represents KMeans/SOM/community/PageRank/bridge/manifold
  as compact features rather than independent document owners.
- [x] 20x20 SOM consistency is checked when X/Y/cell are all present:
  `somCell = somY * 20 + somX`.
- [x] Ontology group contains only concept/entity/tuple references; it does not
  embed full ontology tuple JSON or transfer ontology authority.

### RETRIEVAL-PROFILE-03 — deterministic checksum contract

- [x] Added deterministic SHA-256 profile checksum.
- [x] Object keys are canonicalized before hashing.
- [x] Set-like arrays are deduplicated/sorted before hashing:

- [x] Ordered structural arrays such as `astPath` retain order and therefore
  affect the checksum when reordered.
- [x] Canonical source/workspace revisions affect the checksum.
- [x] Checksum verification detects post-creation profile mutation.
