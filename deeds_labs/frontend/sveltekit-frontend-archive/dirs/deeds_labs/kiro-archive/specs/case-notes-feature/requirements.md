# Case Notes Feature Enhancements - Requirements

## Introduction

This document specifies enhancements to the existing Case Notes feature to add advanced functionality including NES modal UI, case-aware AI contextual chat, full-text search, note versioning, AI memo pinning, and comprehensive case packet export.

## Glossary

- **Case Notes**: User-created or AI-generated notes attached to a legal case
- **Evidence References**: Links between notes and evidence items
- **NES Modal**: A modal dialog styled with YoRHa/NES design system (Bits-UI v2 compatible)
- **Case Synthesis**: Aggregated data from notes, evidence, summaries, and chat history for a case
- **Full-Text Search (FTS)**: PostgreSQL tsvector-based search across note titles and content
- **Note Versioning**: Historical snapshots of note content for diff/audit purposes
- **AI Memo**: Court-ready summary generated by Gemma3-legal from case notes
- **Case Packet**: Comprehensive PDF export including case metadata, evidence index, notes, and AI summary
- **Contextual Chat**: AI chat system aware of case context (notes, evidence, summaries)

## Requirements

### Requirement 1: NES Modal UI for Case Notes

**User Story:** As a prosecutor, I want the Case Notes editor to appear in a styled NES modal so that it feels integrated with the YoRHa design system and doesn't break the visual consistency of the application.

#### Acceptance Criteria

1. WHEN the user clicks the "📝 Case Notes" button THEN the system SHALL display a NES-styled modal with the CaseNotesEditor component
2. WHEN the user clicks outside the modal or the close button THEN the system SHALL close the modal and return focus to the case detail page
3. WHEN the modal is open THEN the system SHALL display a semi-transparent backdrop behind the modal
4. WHEN the modal is displayed THEN the system SHALL show a title bar with "CASE NOTES" text and a close button (✕)
5. WHEN the modal is open THEN the system SHALL prevent scrolling of the background page

### Requirement 2: Case-Aware AI Contextual Chat

**User Story:** As a prosecutor, I want the AI contextual chat to be aware of the current case's notes, evidence, and summaries so that the AI can provide more relevant and contextual responses tied to the specific case I'm working on.

#### Acceptance Criteria

1. WHEN the user opens contextual chat from a case THEN the system SHALL synthesize case data (notes, evidence, summaries, recent chat) and pass it to the LLM
2. WHEN the LLM generates a response THEN the system SHALL include citations in the format [type:id] where type is NOTE, EVID, SUM, or CHAT
3. WHEN the user asks a question about the case THEN the system SHALL only reference data from the current case (not other cases)
4. WHEN the LLM response includes citations THEN the system SHALL make citations clickable to jump to the referenced item
5. WHEN the case synthesis is built THEN the system SHALL include only the most recent 25 notes, 25 evidence items, 10 summaries, and 8 chat turns to keep context manageable

### Requirement 3: Full-Text Search Inside Notes (tsvector)

**User Story:** As a prosecutor, I want to search across all my case notes using full-text search so that I can quickly find relevant notes without manually scrolling through the list.

#### Acceptance Criteria

1. WHEN the user types in a search box in the notes list THEN the system SHALL query notes using PostgreSQL full-text search (tsvector)
2. WHEN search results are returned THEN the system SHALL highlight matching notes in the list
3. WHEN the user clears the search THEN the system SHALL show all notes again
4. WHEN the user searches THEN the system SHALL search both note titles and content
5. WHEN search results are displayed THEN the system SHALL show a preview of matching content (first 240 characters)

### Requirement 4: Note Version Diff View

**User Story:** As a prosecutor, I want to see the history of changes to my notes so that I can track how my case theory has evolved and potentially revert to previous versions if needed.

#### Acceptance Criteria

1. WHEN the user selects a note THEN the system SHALL display a "Version History" button
2. WHEN the user clicks "Version History" THEN the system SHALL show a list of all previous versions of the note with timestamps
3. WHEN the user selects two versions THEN the system SHALL display a side-by-side diff showing what changed
4. WHEN the user clicks "Restore" on a previous version THEN the system SHALL restore that version as the current note content
5. WHEN a note is updated THEN the system SHALL automatically create a version snapshot in the database

### Requirement 5: Save AI Memo as Pinned Note

**User Story:** As a prosecutor, I want to save an AI-generated memo as a pinned note so that it stays at the top of my notes list and serves as a quick reference for the case summary.

#### Acceptance Criteria

1. WHEN the user generates an AI memo THEN the system SHALL display the memo text with a "Save as Pinned Note" button
2. WHEN the user clicks "Save as Pinned Note" THEN the system SHALL create a new note with is_ai=true and is_pinned=true
3. WHEN the memo is saved THEN the system SHALL use the memo text as the note content and auto-generate a title like "AI Memo - [timestamp]"
4. WHEN the memo is saved THEN the system SHALL display a success message and add the note to the top of the notes list
5. WHEN the user saves a memo THEN the system SHALL allow the user to edit the title before saving (optional)

### Requirement 6: Export Full Case Packet (Notes + Evidence Index)

**User Story:** As a prosecutor, I want to export a comprehensive case packet as a PDF that includes all my notes, evidence index, and AI summary so that I can share it with colleagues or include it in case files.

#### Acceptance Criteria

1. WHEN the user clicks "📄 Export Case Packet" THEN the system SHALL generate a PDF containing case metadata, evidence index, pinned notes, and AI summary
2. WHEN the PDF is generated THEN the system SHALL include a cover page with case name, case ID, and generation timestamp
3. WHEN the PDF is generated THEN the system SHALL include an evidence index listing all evidence items with file type and status
4. WHEN the PDF is generated THEN the system SHALL include all pinned notes in order
5. WHEN the PDF is generated THEN the system SHALL include an AI-generated executive summary at the beginning
6. WHEN the PDF is generated THEN the system SHALL include a footer on each page with page number and generation metadata (model, hash of inputs)
7. WHEN the PDF is ready THEN the system SHALL download it with filename format: case_[caseId]_packet_[timestamp].pdf

### Requirement 7: WebGPU Acceleration (Optional)

**User Story:** As a system architect, I want to optionally use WebGPU for client-side operations so that I can accelerate visual analytics and search highlighting in the future without impacting core functionality.

#### Acceptance Criteria

1. WHEN the browser supports WebGPU THEN the system SHALL detect this capability
2. WHEN WebGPU is available THEN the system MAY use it for client-side search highlighting and ranking (future enhancement)
3. WHEN WebGPU is not available THEN the system SHALL fall back to standard JavaScript implementations
4. WHEN using WebGPU THEN the system SHALL NOT impact the core note storage, search, or LLM functionality (server-side only)

## Implementation Notes

- All server code must remain in `+server.ts` files and `$lib/server/*`
- Client components must never import from `$lib/server/*`
- NES modal should use Bits-UI v2 patterns and Svelte 5 runes
- Case synthesis should be built server-side only
- Full-text search uses PostgreSQL tsvector (no external dependencies)
- Note versioning should be automatic on every save
- AI memo saving should be a one-click operation
- Case packet PDF should be deterministic (same inputs = same output for audit purposes)
- WebGPU is optional and should not block any core functionality
