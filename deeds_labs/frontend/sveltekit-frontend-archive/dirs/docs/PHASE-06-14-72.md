## 1. What This Phase Block Does

This trio is all about **"does the app even stand up?"**:

- **Phase 06 – Core (machines + pages)**
  Consolidates routes and runs `ts-check` / `svelte-check` over the _real_ route tree.

- **Phase 14 – Env + Infra Unification**
  Makes sure the `.env` matches the current Ollama / Postgres / Qdrant / Phase 72 setup.

- **Phase 72 – GPU AST Error Brain**
  Takes TypeScript/Svelte error logs and turns them into **dense GPU embeddings** for clustering and triage.

Together they give you:

1. A clean route manifest (no ghost `/cases` routes).
2. A known-good environment wired to your legal stack.
3. A GPU-accelerated "error brain" that can understand and group failures.

### 4.2 Database Schema

Phase 72 uses PostgreSQL with pgvector for semantic error clustering:

```sql
-- Table: phase72_error
CREATE TABLE phase72_error (
  id SERIAL PRIMARY KEY,
  error_hash TEXT UNIQUE NOT NULL,
  file_path TEXT NOT NULL,
  line INTEGER DEFAULT 1,
  col INTEGER DEFAULT 1,
  code TEXT DEFAULT 'VITE_ERROR',
  severity TEXT DEFAULT 'error',
  message TEXT NOT NULL,
  phase INTEGER DEFAULT 72,
  cycle INTEGER DEFAULT 1,
  embedding vector(384),  -- GPU/Ollama embedding for clustering
  occurrence_count INTEGER DEFAULT 1,
  last_seen TIMESTAMP DEFAULT NOW(),
  created_at TIMESTAMP DEFAULT NOW()
);

-- IVFFlat index for fast similarity search
CREATE INDEX phase72_error_embedding_idx
ON phase72_error
USING ivfflat (embedding vector_cosine_ops)
WITH (lists = 100);
```

### 4.3 Embedding Generation

Phase 72 uses a **hybrid approach**:

1. **GPU Addon (Optional):** `ast_error_vectorizer.node` with LibTorch
2. **Ollama Fallback (Default):** `embeddinggemma:latest` model (384 dimensions)

```typescript
// src/lib/phase72/astVectorizer.ts
import { OLLAMA_URL } from '$env/static/private';

export async function vectorizeError(message: string): Promise<number[] | null> {
  try {
    // Try GPU addon first (if built)
    const addonPath = 'build/Release/ast_error_vectorizer.node';
    if (fs.existsSync(addonPath)) {
      const addon = require(addonPath);
      return addon.generateEmbedding(message);
    }
  } catch (err) {
    console.warn('[phase72] GPU addon unavailable, using Ollama fallback');
  }

  // Fallback to Ollama embeddinggemma
  const response = await fetch(`${OLLAMA_URL}/api/embeddings`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      model: 'embeddinggemma:latest',
      prompt: message
    })
  });

  const data = await response.json();
  return data.embedding; // 384-dimensional vector
}
```

## 5. Current Embedding Reality: embeddinggemma

Today, your primary production embeddings are:

- **embeddinggemma** (and friends) for legal text, cases, evidence.

This Phase 72 GPU module is an **extra error-focused engine**, not a replacement.

You can use it in one of two ways:

### Error-only engine (recommended)

- Keep `embeddinggemma` as the main RAG engine.
- Use Phase 72 only for TS/Svelte build logs, with its own small model (`error_encoder.pt`).

### Future engine upgrade

- Replace `error_encoder.pt` with a Gemma/Gemma-legal derived encoder exported to TorchScript / ONNX / TensorRT plan.
- Keep the Node/N-API surface the same; just swap the underlying model.

## 9. Failure Modes & Recovery

### If Phase 72 fails to load

1. **Check environment variable:**
   ```powershell
   $env:PHASE72_ENABLED
   ```

2. **Check GPU addon:**
   ```powershell
   Test-Path "build\Release\ast_error_vectorizer.node"
   ```

3. **Fallback behavior:**
   - GPU addon missing → Uses Ollama `embeddinggemma:latest`
   - Ollama unavailable → Error capture still works, embeddings set to NULL
   - Database down → API returns 500, check DATABASE_URL

### Common Issues

| Issue | Fix |
|-------|-----|
| `Lucia is not defined` | Auth stubbed for Phase 72 testing - restart dev server |
| `Database does not exist` | Check DATABASE_URL points to port 5432 |
| `Ollama connection refused` | Start Ollama: `ollama serve` |
| `Port 5173 already in use` | Kill node processes: `Stop-Process -Name node -Force` |
