# Query: How do I replace export let with props?

## Keywords
export let, props, $props

## Response

Okay, let's tackle replacing `export let` with `$props()` in your Svelte components. This is a core part of migrating to the Svelte 5 Rune syntax.

**Why `export let` is deprecated and why we use `$props()`**

The `export let` syntax, while functional, has limitations and doesn't fully integrate with Svelte's reactivity system.  `$props()` offers a more explicit and controlled way to handle component props, ensuring they are treated as reactive dependencies and are properly typed. It also aligns with the new Rune-based approach to Svelte development, promoting better code clarity and maintainability.

**Migration Steps & Examples**

Here's a step-by-step guide with examples to illustrate the migration process.

**1. Basic Prop Declaration**

*   **Before (using `export let`)**:

    ```svelte
    <!-- MyComponent.svelte -->
    <script>
    	export let name;
    	export let age = 30;
    </script>

    <h1>Hello, {name}!</h1>
    <p>You are {age} years old.</p>
    ```

*   **After (using `$props()`)**:

    ```svelte
    <!-- MyComponent.svelte -->
    <script>
    	let props = $props();
    	$: name = props.name;
    	$: age = props.age;
    </script>

    <h1>Hello, {name}!</h1>
    <p>You are {age} years old.</p>
    ```

    **Explanation:**

    *   We now assign the props object to a variable `props` using `$props()`.
    *   We use `$:` (a derived statement) to extract the individual properties (`name`, `age`) from the `props` object and assign them to local variables.  This makes them reactive and accessible in the template.

**2.  Props with Default Values**

*   **Before:**

    ```svelte
    <!-- AnotherComponent.svelte -->
    <script>
    	export let message = "Default Message";
    </script>

    <p>{message}</p>
    ```

*   **After:**

    ```svelte
    <!-- AnotherComponent.svelte -->
    <script>
    	let props = $props();
    	$: message = props.message || "Default Message";
    </script>

    <p>{message}</p>
    ```

    **Explanation:**

    *   Similar to the previous example, we extract the `message` prop.
    *   We use the OR operator (`||`) to provide a default value if the prop is not explicitly passed.

**3.  Component with Multiple Props**

*   **Before:**

    ```svelte
    <!-- Product.svelte -->
    <script>
    	export let title;
    	export let price;
    	export let imageUrl;
    </script>

    <img src={imageUrl} alt={title} />
    <h2>{title}</h2>
    <p>${price}</p>
    ```

*   **After:**

    ```svelte
    <!-- Product.svelte -->
    <script>
    	let props = $props();
    	$: title = props.title;
    	$: price = props.price;
    	$: imageUrl = props.imageUrl;
    </script>

    <img src={imageUrl} alt={title} />
    <h2>{title}</h2>
    <p>${price}</p>
    ```

    **Explanation:**

    *   We extract all the props into local variables using derived statements.

**4.  Props in a Layout or Page file (SvelteKit)**

*   **Before (SvelteKit, older versions):**

    ```svelte
    <!-- +page.svelte -->
    <script>
    	export let data;
    </script>

    <h1>{data.title}</h1>
    ```

*   **After (SvelteKit, Svelte 5):**

    ```svelte
    <!-- +page.svelte -->
    <script>
    	let props = $props();
    	$: data = props.data;
    </script>

    <h1>{data.title}</h1>
    ```

    **Explanation:**

    *   We access the `data` prop (passed from the load function) through the `props` object.

**Important Considerations:**

*   **Type Safety:**  With `$props()`, you can leverage TypeScript more effectively to define the expected shape of your props.  This enhances code reliability and helps catch errors early.
*   **Reactivity:**  Changes to props passed to a component using `$props()` will automatically trigger updates in the component's reactive statements (`$:`) and the template.
*   **Prop Drilling:**  If you find yourself passing props down through multiple levels of components, consider using Svelte's context API or stores to simplify prop management.

**Summary**

Migrating from `export let` to `$props()` involves a small refactoring effort but brings significant benefits in terms of code clarity, reactivity, and type safety. By extracting props into a `props` object and using derived statements (`$:`) to access them, you're embracing the Svelte 5 Rune syntax and building more robust and maintainable components.
