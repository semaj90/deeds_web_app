# Manual Startup Guide (Troubleshooting Mode)

If the automated startup script fails, use this manual startup sequence.

## Prerequisites

```powershell
# Check if Go is installed
go version

# Check if Node/npm is installed
node --version
npm --version

# Check if Caddy exists
Test-Path .\caddy.exe
```

## Step-by-Step Startup

### 1. Free Occupied Ports (if needed)

```powershell
# Kill processes on port 5178 (Caddy)
Get-NetTCPConnection -LocalPort 5178 -ErrorAction SilentlyContinue |
  ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }

# Kill processes on other ports if needed
5173, 8100, 8101 | ForEach-Object {
  Get-NetTCPConnection -LocalPort $_ -ErrorAction SilentlyContinue |
    ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
}
```

### 2. Start WebSocket Orchestrator (Terminal 1)

```powershell
cd go-services\ws-orchestrator
go run main.go
```

**Expected Output:**
```
WebSocket Orchestrator starting...
Listening on :5173
Service registered: enhanced-rag on port 5173
Generated .ws-registry.json
Generated .env.local
Generated Caddyfile.ws
```

**Troubleshooting:**
- If it fails to compile: `go mod download`
- If it doesn't generate files: Check file permissions
- If port 5173 is occupied: It will try 5174, 5175, etc.

### 3. Start QUIC Bridge (Terminal 2)

```powershell
cd go-services\quic-bridge
go run main.go
```

**Expected Output:**
```
QUIC Bridge starting...
HTTP Fallback Server: http://localhost:8101
QUIC/HTTP3 Server: https://localhost:8100 (requires TLS certificates)
```

**Troubleshooting:**
- If compilation fails: `go mod download`
- HTTP/3 is disabled until TLS certificates are generated
- HTTP fallback on port 8101 should work immediately

### 4. Start Caddy Proxy (Terminal 3)

```powershell
cd sveltekit-frontend
..\caddy.exe run --config Caddyfile.development
```

**Alternative if caddy.exe not found:**
```powershell
# Download Caddy
Invoke-WebRequest -Uri "https://caddyserver.com/api/download?os=windows&arch=amd64" -OutFile caddy.zip
Expand-Archive caddy.zip -DestinationPath .
.\caddy.exe run --config Caddyfile.development
```

**Expected Output:**
```
Caddy 2.x
http://localhost:5178
Serving HTTP on :5178
```

**Troubleshooting:**
- If port 5178 is in use: Edit `Caddyfile.development` and change port
- If import fails: Check that `../../Caddyfile.ws` exists
- Check for syntax errors in Caddyfile

### 5. Start Vite Dev Server (Terminal 4)

```powershell
cd sveltekit-frontend
npm run dev
```

**Expected Output:**
```
VITE ready in XXX ms
Local:   http://localhost:5174
Network: use --host to expose
```

**Troubleshooting:**
- If dependencies missing: `npm install`
- If port 5173/5174 occupied: Vite will auto-increment port
- Check `.env.local` was generated by orchestrator

## Verification

### Check Service Registry

```powershell
# View generated registry
cat sveltekit-frontend\.ws-registry.json | ConvertFrom-Json | Format-Table

# Expected output:
# name         port endpoint                     protocol
# ----         ---- --------                     --------
# enhanced-rag 5173 /ws/enhanced-rag/v1/search  ws
```

### Test WebSocket Connection

```powershell
# Test orchestrator health
Invoke-RestMethod -Uri "http://localhost:5173/health"

# Test QUIC bridge
Invoke-RestMethod -Uri "http://localhost:8101/health"
```

### Test in Browser

Open browser to `http://localhost:5178` (Caddy proxy) or `http://localhost:5174` (direct Vite).

**Browser Console Test:**
```javascript
// Fetch service registry
const registry = await fetch('/.ws-registry.json').then(r => r.json());
console.log('Registry:', registry);

// Connect to WebSocket
const service = registry.find(s => s.name === 'enhanced-rag');
const ws = new WebSocket(`ws://localhost:${service.port}${service.endpoint}`);

ws.onopen = () => {
  console.log('✅ WebSocket connected');
  ws.send(JSON.stringify({
    type: 'legal_search',
    query: 'test query',
    context: {}
  }));
};

ws.onmessage = (e) => {
  const data = JSON.parse(e.data);
  console.log('📥 Response:', data);
};

ws.onerror = (e) => console.error('❌ WebSocket error:', e);
```

## Common Issues

### Issue: WebSocket Orchestrator Won't Start

**Symptoms:**
- Hangs at "Starting..."
- No `.ws-registry.json` file generated
- Port binding errors

**Solutions:**
```powershell
# 1. Check if Go dependencies are installed
cd go-services\ws-orchestrator
go mod tidy
go mod download

# 2. Try manual port specification
$env:WS_PORT="5173"
go run main.go

# 3. Check for compilation errors
go build -v .
```

### Issue: Caddy Not Found

**Solutions:**
```powershell
# Option 1: Use existing caddy.exe
.\caddy.exe version

# Option 2: Download fresh copy
Invoke-WebRequest -Uri "https://caddyserver.com/api/download?os=windows&arch=amd64" -OutFile caddy.zip
Expand-Archive caddy.zip -Force
.\caddy.exe version

# Option 3: Install via Chocolatey
choco install caddy
```

### Issue: Port Already in Use

**Identify Process:**
```powershell
Get-NetTCPConnection -LocalPort 5178 |
  Select-Object -ExpandProperty OwningProcess |
  ForEach-Object { Get-Process -Id $_ }
```

**Kill Process:**
```powershell
# By port
Get-NetTCPConnection -LocalPort 5178 |
  ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }

# By name
Stop-Process -Name caddy -Force
Stop-Process -Name node -Force
Stop-Process -Name go -Force
```

### Issue: Frontend Can't Connect to WebSocket

**Symptoms:**
- `ConnectionResetError: [WinError 10054]`
- Browser shows WebSocket connection failed

**Solutions:**
```powershell
# 1. Verify registry exists
Test-Path sveltekit-frontend\.ws-registry.json

# 2. Check registry contents
cat sveltekit-frontend\.ws-registry.json

# 3. Test WebSocket endpoint directly
curl http://localhost:5173/health

# 4. Restart orchestrator to regenerate registry
cd go-services\ws-orchestrator
go run main.go
```

## Service Startup Order (Important!)

**Correct Order:**
1. WebSocket Orchestrator (generates registry)
2. QUIC Bridge (optional, for HTTP/3)
3. Caddy Proxy (imports WebSocket routes)
4. Vite Dev Server (uses registry for auto-discovery)

**Why This Matters:**
- Caddy needs `Caddyfile.ws` from orchestrator
- Frontend needs `.ws-registry.json` for service discovery
- `.env.local` provides fallback configuration

## Stop All Services

```powershell
# Option 1: Use stop script
.\stop-realtime-stack.ps1

# Option 2: Manual cleanup
Stop-Process -Name caddy, node, go -Force -ErrorAction SilentlyContinue

# Option 3: Close PowerShell windows
# Just close each terminal window running a service
```

## Quick Diagnostic

```powershell
# One-liner to check all services
@(
  @{Port=5173; Name="WebSocket Orchestrator"},
  @{Port=8100; Name="QUIC Bridge (HTTPS)"},
  @{Port=8101; Name="QUIC Bridge (HTTP)"},
  @{Port=5178; Name="Caddy Proxy"},
  @{Port=5174; Name="Vite Dev"}
) | ForEach-Object {
  $inUse = Get-NetTCPConnection -LocalPort $_.Port -ErrorAction SilentlyContinue
  $status = if ($inUse) { "✅ Running" } else { "❌ Stopped" }
  Write-Host "$status - $($_.Name) (port $($_.Port))"
}
```

## Next Steps After Manual Start

Once all services are running:

1. **Run Integration Tests:**
   ```powershell
   node test-realtime-integration.mjs
   ```

2. **Generate TLS Certificates (for WebTransport):**
   ```powershell
   New-Item -ItemType Directory -Force -Path go-services\quic-bridge\certs

   openssl req -x509 -newkey rsa:4096 `
     -keyout go-services\quic-bridge\certs\key.pem `
     -out go-services\quic-bridge\certs\cert.pem `
     -days 365 -nodes -subj "/CN=localhost"
   ```

3. **Enable HTTP/3 in QUIC Bridge:**
   - Uncomment HTTP/3 server code in `go-services/quic-bridge/main.go`
   - Restart QUIC bridge

4. **Test WebTransport:**
   ```javascript
   // Browser console (requires HTTPS context)
   const transport = new WebTransport('https://localhost:8100');
   await transport.ready;
   console.log('✅ WebTransport connected');
   ```
