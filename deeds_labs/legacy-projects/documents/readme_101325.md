Acceleration roadmap: embeddings, clustering & integration (2025-10-13)

This document summarizes a low-risk roadmap to accelerate embeddings and clustering for low-latency semantic similarity and how to wire it into the existing stack (SvelteKit 2, Drizzle, pgvector, Qdrant, Redis, RabbitMQ, XState). It also points to relevant artifacts already present in the repo.

What exists in the codebase (quick inventory)
- Triton/TensorRT model configs: `triton-models/legal_embedding/config.pbtxt` and `triton-models/legal_generation/config.pbtxt` (Triton model repo skeletons)
- TensorRT smoke-test: `tensorrt-smoketest/` (CMake smoke-test + README)
- webgpu starter & embeddings: `webgpu-redis-starter-repo/` (FastAPI, ONNX, embedding model usage and server-side orchestrator)
- Go microservices with GPU/embedding placeholders: `go-microservice/` (many files show embedding, GPU, Triton, Ollama integration)
- Environment templates for TensorRT: `ubuntu-tensorrt/.env.tensorrt`

High-level recommendations
- Server: Convert trained embedding model → ONNX → TensorRT/Triton. Serve via Triton for HTTP/gRPC endpoints.
- Clustering: Run SOM/k-means offline or as a nearline microservice (use cuML/FAISS for GPU acceleration). Keep clustering out of request-critical path.
- Browser: Use `transformers.js` or ONNX WebGPU for small models; use SharedArrayBuffer + Web Workers (COOP/COEP required) to parallelize CPU-bound steps.
- Orchestration: Upload → publish RabbitMQ event → worker(s) consume → batch to Triton → write to Postgres/pgvector & Qdrant → cache in Redis → notify frontend via WebSocket/XState.

Concrete next-step artifacts (created in this commit)
- `src/workers/embedding-worker.ts` — Node worker template that calls Triton HTTP inference, writes vectors to Postgres (Drizzle), optionally Qdrant, and publishes RabbitMQ ack.
- `sveltekit-frontend/static/examples/embed-worker/` — browser example demonstrating SharedArrayBuffer + Web Worker pattern and COOP/COEP notes.
- `scripts/benchmark_similarity.js` — tiny script to compare baseline vs optimized embeddings and report cosine similarity deltas.

Operational notes & pitfalls
- INT8 quantization requires calibration data and will alter embedding fidelity — always validate the similarity deltas before promoting to production.
- SharedArrayBuffer requires COOP/COEP headers on pages that use it; configure SvelteKit to send those headers only for specific routes if necessary.
- Keep heavy GPU workloads out of SSR routes. Use asynchronous worker processing and notify the UI when results are available.
