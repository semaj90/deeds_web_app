# MTP/Speculative Decoding Architecture Concepts (June 26)

## 💡 Core Principles
The goal is to maximize GPU utilization by addressing both **throughput** (handling many users/requests simultaneously) and **latency** (reducing time taken for a single user's response).

**1. Continuous Batching (Throughput Focus):**
*   **What it is:** Scheduling requests in continuous batches.
*   **Benefit:** Ensures the GPU's memory is always packed tightly with active requests, preventing idle time and maximizing overall requests processed over time.
*   **Concept:** Spatial efficiency.

**2. Speculative Decoding / MTP (Latency Focus):**
*   **What it is:** Using a small, fast "draft" model (e.g., `gemma3270m`) to predict several future tokens, which the heavy "target" model then verifies in a single forward pass.
*   **Benefit:** Generates multiple tokens in the time usually required for one, drastically reducing perceived latency for the user.
*   **Concept:** Temporal efficiency.

**3. The Synergy (The Ideal State):**
*   Modern engines (vLLM, etc.) combine both: Continuous Batching ensures the GPU is busy, and Speculative Decoding ensures that every time it's busy, it's generating tokens as fast as possible.

## 🧠 Proposed OpenCode/Legal-AI Architecture Flow
The system should operate in distinct, sequential lanes:

**Lane 0: Request Ingestion (The Router)**
1.  **Input:** User prompt.
2.  **Action:** Run through `gemma3270m` (or similar lightweight model) for:
    *   Cache hit check (Exact Match / Semantic Summary Cache).
    *   Tool/Intent resolution (Pattern recognition cache hit?).
    *   If a clear path is found, return the small result and stop.
3.  **Output:** If a clear path is found, return small, cached, or local results. If not, proceed to retrieval.

**Lane 1: Retrieval/Intent Execution (The Work)**
1.  **Action:** Execute the best-guess tool (e.g., `atlas-tools_find_dependencies`, `mcp-toolchain`).
2.  **Output:** A highly compressed, structured context package (the "Implementation Brief").

**Lane 2: Generation (The Heavy Lift)**
1.  **Action:** Feed the structured context into the primary large model (`Gemma-4 31B`, `Triton`, `vLLM` serving).
2.  **Optimization:** Must use MTP/Speculative Decoding features to generate the output efficiently.

## ⚙️ Model Constraints & Implementation Notes
*   **Drafting Models:** The draft model must use a compatible tokenizer with the target model.
*   **Execution:** Start with `draftless` speculation for maximum compatibility. Only move to `draft-mtp` when the target model is confirmed to have MTP heads.

**Rule of Thumb:** Semantic routing saves compute, speculative decoding speeds generation. Keep them separate.
