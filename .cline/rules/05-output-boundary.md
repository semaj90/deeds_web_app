# Output Boundary

- Do not write internal reasoning, scratch notes, or chain-of-thought into files.
- When producing reports or task updates, write only concise evidence: commands, results, file paths, counts, blockers, and next actions.
- If a task needs explanation, summarize the decision and evidence in plain prose; do not dump the full intermediate analysis.
- Keep generated markdown and JSON artifacts compact and machine-readable.
- If a prompt asks for "thinking", "reasoning", or "analysis", keep that in the conversation response only, not in workspace files.
